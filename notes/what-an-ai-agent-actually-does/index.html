What an agent actually does.

The useful difference is the ability to move from a request to a tool action and a checked result.

Twinthos · Published 21 October 2026 · Updated 8 November 2026 · 2 min read

THE SHORT ANSWER

In brief

Define the job through inputs, allowed actions and observable outputs.

A request starts the work

An agent receives a goal and context, chooses a next step and may call a tool. Anthropic distinguishes agents that select their own steps from workflows with predetermined paths. For a business, the important question is which approach makes the particular job dependable.

Tools make the action possible

A browser can read an approved website. A file tool can prepare a report. An email tool can draft a response. Each capability needs an account, permission and a clear definition of success. The model’s confidence is not proof that the external action happened.

An example: preparing a customer reply

Imagine a request asking whether a service is suitable. The agent could read the enquiry, consult approved service details and prepare a draft. If information is missing, it should flag the gap. If sending requires approval, drafting must not silently become sending. This is a possible workflow, not a report of a client deployment.

Check the result outside the conversation

Look for the saved document, the correct record or the approved draft. Record failed tool calls and incomplete steps. When comparing systems, ask the same question every time: can someone verify what happened without relying on the agent’s own summary?

IN PRACTICE / ILLUSTRATIVE SCENARIO

Trace a task through the actual tools

Take a customer enquiry asking for a quote. The agent may receive the request, retrieve a current price list, find gaps, draft a proposal and submit it to a reviewer. Those operations are distinct. A text response saying 'I have updated the record' is not evidence that the database was changed. The owner should be able to inspect the destination record or generated file. If the source prices are missing or outdated, the workflow should stop or ask rather than guess. This same discipline applies to browser actions, repositories, spreadsheets and messaging channels.

THE OPERATING DECISION

The job specification matters more than autonomy

Write the trigger, the approved sources, the permitted tools, the allowed outputs and the stop conditions in plain language. Decide which steps are deterministic: checking whether a required field exists may not need a language model. Reserve model decisions for cases where flexible interpretation adds value and can be reviewed. Test what happens when a connector returns an error halfway through the job. A useful agent is one whose results and failures can be accounted for, not one that makes the greatest number of calls.

DIRECT ANSWER

How is an AI agent different from a chatbot?

A chatbot can help produce an answer. An agent may be configured to select and use tools to carry out steps. What matters operationally is the written job, actual permissions and verifiable result, not the name.

THE PRACTICAL TEST

Describe one job in three lines: what starts it, what tools it may use and what evidence proves completion.
