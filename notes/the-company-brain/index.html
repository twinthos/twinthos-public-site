Memory needs ownership, too.

A Company Brain is useful when its knowledge is current, attributable and available to the right people.

Twinthos · Published 21 October 2026 · Updated 8 November 2026 · 2 min read

THE SHORT ANSWER

In brief

The valuable asset is approved context that can be maintained, corrected and used within a defined scope.

Start with a knowledge map

What information does the job actually need? List the procedures, policies, responsibilities and project records that affect the answer. Keep the first scope small enough for an owner to review. Copying every company file into a search system can make the knowledge harder to govern.

Separate fact from inference

A useful record says where a statement came from and when it was checked. A customer’s confirmed requirement, a colleague’s suggestion and an agent’s guess should not become indistinguishable memories. Give uncertain information an explicit status and an owner who can resolve it.

Make updates part of the job

Policies change. Projects close. People move roles. Define a review process and a way to correct or retire information. In our proposed Company Brain structure, identity, rules, responsibilities and project history are separate categories so that changes can be traced.

Treat retrieval as access

A knowledge system should only return information the requesting workflow is entitled to use. Decide how company separation, permissions, retention and deletion will work in the actual deployment. These controls need tests; they are not guaranteed by the word “memory”.

Know what it cannot promise

Persistent storage does not make a model infallible. The system may retrieve the wrong source or interpret a correct source badly. Make important answers reviewable against their origin and allow the agent to report that the available information is insufficient.

IN PRACTICE / ILLUSTRATIVE SCENARIO

A single policy, three incompatible answers

Suppose a business changes its refund policy on Monday. A team member remembers the old rule, an old PDF remains in a shared folder and a new policy is approved by management. An agent that simply searches for related text may retrieve the wrong version. A useful Company Brain needs a source register: the current policy owner, its approval date, the superseded file and the groups entitled to retrieve it. The model should be able to identify the applicable source or request clarification when conflicting versions remain. The goal is not an artificial memory that can never be wrong; it is an organised process for knowing what is authoritative.

THE OPERATING DECISION

Make correction a normal workflow

For each important piece of knowledge, record the provenance, owner, update trigger and permissions. Decide whether a human can amend it directly and how downstream workflows learn that the answer changed. Consider deletion and export before deployment, particularly where customer data is involved. Retrieval testing should include two clients with similarly named records and an intentionally outdated document; the agent must not mix them. Documenting this boundary can be more important than expanding the number of documents a system can read.

DIRECT ANSWER

Does persistent memory mean the agent cannot forget?

No. Persistent storage can hold information across sessions, but retrieval, permissions, relevance and interpretation can still fail. Verify important answers against approved, current sources.

THE PRACTICAL TEST

Select one important company rule. Trace its source, owner, access permissions and correction path before putting it into an agent.
